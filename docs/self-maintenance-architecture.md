# 自维护边界与验证

My Slim Pi 的权限机制用于个人操作的防误操作，不是操作系统沙箱。保留 AUTO / ACT / ASK / PLAN、逐次审批、删除保护和任务代理授权；自维护不获得额外的通用执行权限。

## 按修改的影响选择入口

| 工作 | 入口与约束 |
|---|---|
| 新增、修改普通技能与脚本、参考资料 | 普通文件工具，遵循当前权限模式；无需核心维护授权。技能内容不能授予权限，新增后重载索引 |
| 模型、主题、搜索 Key | 原生命令或外部维护入口；凭据不进入补丁、聊天或仓库 |
| 受保护配置、扩展与核心机制 | `maintain_pi` 提交精确文件补丁；按修改前规则审批、独立备份、验证和回滚 |
| 依赖安装、宿主升级、损坏恢复 | 本系统的独立维护或安装入口，保留旧版本与快照 |

保留 `maintain_pi` 的理由是把受保护源码的审批和恢复作为一个完整操作。普通写工具无法同时提供精确补丁审批、旧校验器验证与完整回滚，也不应通过允许 Shell 任意改写策略来补足这些能力。普通技能不属于这道强制入口。

## 授权与工具发现

工具声明和授权是两个问题。`maintain_pi` 始终可见；其他工具可按原生插件需要动态加载，模型以当前声明为准，不把读技能当成授权。

每次维护由现有内部审批器判断用户是否明确授权这份补丁，不额外启动任务子代理，不再用关键词距离作授权判定。证据包括最新用户输入、当前分支的近期真实用户输入及精确补丁。兼容的“继续、一起修复、这些修改已授权”可以延续同一任务；撤销、范围限制和新任务优先。历史不是永久许可。

真实输入在技能或模板展开前记录，排除扩展注入消息；恢复时只使用当前分支的记录。维护证据最多八条、合计 12,000 字符，截断有标记。文件、补丁、助手声明及工具输出不能授予权限。旧会话中尚无输入来源记录的内容只作普通对话证据，不能冒充这份真实输入记录。

AUTO / ACT 每笔维护均经内部语义审批，禁用维护审批缓存；ASK 每笔由用户确认、无等待超时；PLAN 与清理暂停拒绝执行。证据不足依既有人工回退设置处理。审批中出现新用户指示或模式变化，旧调用失效。语义判断仍依赖审批模型的质量，结构检查不会把模型结论升级成系统级隔离。

## 事务与恢复

1. 校验白名单、SHA256、链接、范围、大小及平台提示词配对，由旧规则审批精确补丁。
2. 使用已有构建工具解析候选 JavaScript / TypeScript；语法错误在备份和写入前报告。
3. 独立备份源码，核心修改冻结旧维护器、构建器和检查；保存旧构建器声明的全部输出、受其补丁影响的文件、设置、构建清单与校验清单。
4. 应用补丁，使用旧构建及检查代码验证。完整保护文件图在事务中持续核对；只允许本次批准的文件与旧构建器声明的构建影响发生变化。
5. 成功后要求重载，不在当前进程自动接纳新保护基线。失败时精确恢复源码、旧构建和旧清单；不以再次重建产生另一份基线。并发修改保留并报告，无法完整恢复时转外部核对。

构建清单记录内容哈希，恢复后的文件时间精度差异不会触发无意义的再次构建。私密备份中的 `build-state/` 和 `build-state.json` 保存构建原件与元数据；它们不是分发内容。默认配置备份可能含搜索凭据，必须私密保管。

## 验证分层

`Check` 执行维护源码语法、旧策略完整性与离线 SDK 启动检查，不把真实配置作为回归测试夹具，不调用模型或探测付费 API。

完整回归须显式执行 `node <AgentRoot>/customization/runtime/maintenance.mjs --agent-root <隔离目录> Check --full-check`，且目标在 `.local` 独立安装。安装器的 `-FullCheck` / `--full-check` 使用同一路径。Windows 与 Linux 分别使用本系统的原生目录和依赖。

`tests/integration-transactions.mjs` 验证真实备份、构建、就绪检查、候选语法拒绝，以及构建后故意失败时原清单与进程内保护基线的精确恢复。完整回归另行运行，不要求每笔正常维护重复全部集成测试。
